[#consent_binding]
=== Binding

The binding a consent reference carries depends on its domain:

* For `identity` consent, the reference SHALL contain *bound_actor*: a hashed URI referencing the `cawg.identity` assertion of the named actor, the participant, to whom the consent applies.
* For `asset` consent, the reference binds to the asset carrying the manifest, and MAY contain *asset_creator*: a hashed URI referencing the `cawg.identity` assertion of the asset-creator named actor.
No person-shaped binding is required for asset consent.

Where a manifest carries more than one `cawg.identity` assertion, the hashed URI identifies the specific assertion instance by its label.

Hash references among consent and identity assertions SHALL NOT form a cycle.
An identity assertion referenced by a consent assertion, through `bound_actor` or `asset_creator`, SHALL NOT directly or indirectly hash-reference that consent assertion.

NOTE: For identity consent, the assertions are constructed in this order.
First, the participant's identity assertion (A) is completed.
Second, the consent assertion (C) is created, with `bound_actor` referencing A.
Third, an endorsing identity assertion (B), held by the participant or the participant's authorized representative, is created and lists C among its referenced assertions.
A does not reference C, so no cycle forms.
The same order applies to `asset_creator` for asset consent.

A consent reference is bound to its asset by its placement in the asset's C2PA Manifest, which the C2PA hard binding ties to the asset's content.
A consent reference SHOULD also identify the asset by reference to that content binding, so that a reference encountered apart from its manifest can be matched to its asset.
A field for this purpose is anticipated in a future version (xref:consent_future_work[xrefstyle=full]).

Consistent with existing CAWG practice, a consent reference is associated with a named actor by reference to that actor's `cawg.identity` assertion.

[source,json]
----
{
  "consent_references": [
    {
      "uri": "https://authority.example.org/identity/{record-id}",
      "reference_type": "consent_authority",
      "consent_domain": "identity",
      "bound_actor": {
        "url": "self#jumbf=c2pa.assertions/cawg.identity",
        "hash": "{hash of the participant's identity assertion}"
      }
    },
    {
      "uri": "https://authority.example.org/asset/{record-id}",
      "reference_type": "permission_record",
      "consent_domain": "asset",
      "asset_creator": {
        "url": "self#jumbf=c2pa.assertions/cawg.identity__1",
        "hash": "{hash of the asset creator's identity assertion}"
      }
    }
  ]
}
----

If an asset is separated from its manifest, the standard C2PA mechanisms for linking a disconnected manifest, including watermark-based recovery, are used to relocate the manifest and therefore the consent reference.
